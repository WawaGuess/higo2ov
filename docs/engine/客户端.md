# OpenViking HTTP 客户端

## 概述

`OpenVikingClient` 封装了所有 OpenViking HTTP API 调用，基于 `httpx.AsyncClient` 实现异步请求。

---

## 核心 API

| 方法 | HTTP | 路径 | 说明 |
|------|------|------|------|
| `health_check()` | GET | `/health` | 健康检查 |
| `add_session_message()` | POST | `/api/v1/sessions/{id}/messages` | 追加消息到 session |
| `get_session()` | GET | `/api/v1/sessions/{id}` | 获取 session 元数据（含 pending_tokens） |
| `get_session_context()` | GET | `/api/v1/sessions/{id}/context` | 获取组装后的会话上下文 |
| `commit_session()` | POST | `/api/v1/sessions/{id}/commit` | 归档 + 记忆提取 |
| `find()` | POST | `/api/v1/search/find` | 语义搜索 |
| `get_task()` | GET | `/api/v1/tasks/{task_id}` | 轮询后台任务状态 |
| `get_session_archive()` | GET | `/api/v1/sessions/{id}/archives/{archiveId}` | 获取归档详情 |
| `delete_session()` | DELETE | `/api/v1/sessions/{id}` | 删除 session |
| `delete_uri()` | DELETE | `/api/v1/fs?uri=...` | 删除 URI 对应资源 |

## URI 规范化

### 作用域隔离

`_build_canonical_root()` 根据配置构建规范 URI：

```python
# user scope
if isolate_user_scope_by_agent:
    f"viking://user/{user_id}/agent/{agent_id}"
else:
    f"viking://user/{user_id}"

# agent scope
if isolate_agent_scope_by_user:
    f"viking://agent/{agent_id}/user/{user_id}"
else:
    f"viking://agent/{agent_id}"
```

### 目标 URI 规范化

`_normalize_target_uri()` 将简写 URI 扩展为完整 URI：
- 输入：`viking://user/memories`
- 输出：`viking://user/default/agent/higo-extension/memories`（取决于配置）

## 请求头

| Header | 来源 | 说明 |
|--------|------|------|
| `X-API-Key` | `config.api_key` | 认证密钥 |
| `X-OpenViking-User` | `config.user_id` | 用户标识 |
| `X-OpenViking-Agent` | `config.agent_id` 或参数 | Agent 标识 |

---

## 错误处理

`_parse()` 统一处理响应：
1. `resp.raise_for_status()` — HTTP 非 2xx 抛异常
2. 检查 `data.status == "error"` — OV 业务错误
3. 返回 `data.result` 或完整 `data`

请求异常被包装为 `RuntimeError`，由调用方捕获。
