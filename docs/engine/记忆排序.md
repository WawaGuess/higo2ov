# 记忆排序与预算

## 概述

`engine/memory_ranking.py` 实现记忆搜索结果的后处理：去重、query-aware 排序、叶子优先选择、token 预算截断。

---

## 去重

### _memory_dedupe_key(result)

| 记忆类型 | 去重键 |
|---------|--------|
| events / cases | `uri` |
| 其他 | `abstract + category + normalized_text` |

### _normalize_dedupe_text(text)

小写 + 折叠空白：`" Hello   World "` → `"hello world"`

---

## Query-Aware 排序

### _rank_for_injection(result, query)

```
final_score = base_score
            + leaf_boost(0.12)       # level == 2
            + event_boost(0.1)       # wants_temporal and is event
            + preference_boost(0.08) # wants_preference and is preference
            + lexical_overlap(max0.2) # 查询词在 URI/abstract 中的匹配
```

### Query Profile

```python
{
    "tokens": ["typescript", "编程"],  # 去除停用词后的查询词
    "wants_preference": True,        # 是否含偏好相关词
    "wants_temporal": False,         # 是否含时间相关词
}
```

### 停用词

```python
{"what", "when", "where", "which", "who", "the", "and", "for", "your", "you", ...}
```

## 选择策略

### pick_memories_for_injection(items, limit, query_text, score_threshold)

```
1. Query-aware 排序
2. 去重
3. 提取 leaf memories（level == 2）
4. 若 leaves >= limit：只返回 leaves[:limit]
5. 否则：leaves + non-leaf fallback（按 score_threshold 过滤）
```

**Leaf 优先的原因**：level == 2 是完整内容记忆，level == 1 是目录/索引，信息密度更高。

## Token 预算

### build_memory_lines_with_budget(results, token_budget)

- 第一条记忆**强制包含**（有界溢出）
- 后续条目检查 `total_tokens <= token_budget`
- 使用 `_count_tokens()`（tiktoken 优先，fallback 字符估算）
- 格式：`- [{category}] {content} ({score:.0%})`

## Category 推导

### _derive_category_from_uri(uri)

OpenViking 搜索返回的 `category` 字段为空（服务端 bug），从 URI 路径推导：

| URI 路径片段 | Category |
|-------------|----------|
| `/preferences` | `preferences` |
| `/entities` | `entities` |
| `/events` | `events` |
| `/profile` | `profile` |
| `/patterns` | `patterns` |
| `/cases` | `cases` |
| 其他 | `memory` |
