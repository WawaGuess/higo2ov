# 开发规范

## 文档同步规范

修改代码时，必须主动检查并同步更新相关文档的锚点。

### 修改前检查

1. 打开待修改的代码文件，查看顶部 `# 相关文档:` 注释
2. 打开对应文档，核对 `## 相关代码` 区块是否包含本次要改的函数/类
3. 如果文档不存在或锚点缺失，先补文档再改代码

### 修改后同步

1. 函数签名变更 → 更新文档 `## 相关代码` 表格中的函数名
2. 新增核心函数/类 → 在对应文档中添加表格行
3. 新增代码文件 → 在文件顶部添加 `# 相关文档:` 注释
4. 删除代码文件/函数 → 同步删除文档中的锚点行

### 修改后必查清单（防遗漏）

代码改动完成后，执行以下检查：

- [ ] `grep -r "旧文件名" docs/` — 全局搜索是否还有文档引用旧文件路径
- [ ] `grep -r "旧函数名" docs/` — 全局搜索是否还有文档引用旧函数名
- [ ] `docs/架构总览.md` — 模块关系树是否同步（新增/删除目录时必查）
- [ ] `docs/README.md` — 目录结构和快速导航是否同步（新增/删除文档时必查）
- [ ] `docs/开发规范.md` — 快速检查命令中的路径列表是否同步

### 快速检查命令

```bash
# 检查哪些代码文件缺少文档锚点
grep -RL "^# 相关文档:" engine/*.py monitor/*.py main.py

# 检查哪些 docs 文件引用了不存在的代码文件
grep -r "engine/" docs/ | grep -v "archive/" | sed 's/.*`\(engine\/[^`]*\)`.*/\1/' | sort -u | while read f; do [ -f "$f" ] || echo "missing: $f"; done
```

## 编码约定

- 使用类型注解（`from __future__ import annotations` 启用 PEP 563）
- 异步函数优先使用 `async/await`
- 日志统一使用 `logging.getLogger(__name__)`
- 环境变量配置集中放在 `engine/config.py`
