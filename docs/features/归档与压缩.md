# 归档与压缩

## 概述

归档（commit）将 OpenViking session 中的活跃消息压缩为归档摘要并提取长期记忆。支持两种触发方式：
- **异步归档**：transform/result 后自动检查阈值触发
- **强制归档**：通过 `POST /compact` 端点同步触发

---

## 异步归档

### 触发时机

Transform 和 Result 阶段都会异步触发 `_maybe_commit()`：

```python
asyncio.create_task(self._maybe_commit(ov_session_id, user_id=user_id))
```

使用 `create_task` 不阻塞 Higo 响应。

### 阈值检查

```python
session_info = await client.get_session(ov_session_id)
pending_tokens = session_info.get("pending_tokens", 0)
if pending_tokens > self.config.commit_token_threshold:
    await client.commit_session(ov_session_id, wait=False)
```

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `OPENVIKING_COMMIT_TOKEN_THRESHOLD` | `8000` | 自动归档触发阈值 |

### 两阶段 Commit

**Phase 1**（立即返回）：
- `POST /commit` 返回 `task_id`
- session 被归档，活跃消息清空

**Phase 2**（异步执行）：
- OV 后台提取记忆（facts、events 等分类）
- 通过 `GET /tasks/{task_id}` 轮询状态
- 当 `wait=True` 时，客户端轮询直到 completed/failed/timeout

---

## 强制归档

### 端点

```bash
POST /compact
Body: {"sessionId": "xxx", "session": {"userId": "u001"}}
```

### 流程

1. Bypass 检查
2. Resolve client
3. 预提交 GET context → `tokens_before`
4. `commit(wait=True)` → 同步等待 Phase 2 完成
5. 后提交 GET context → `tokens_after`、`latest_archive_overview`
6. 返回摘要、firstKeptEntryId、tokensBefore/After

### 响应

```json
{
  "ok": true,
  "compacted": true,
  "reason": "commit_completed",
  "result": {
    "summary": "归档摘要内容...",
    "firstKeptEntryId": "archive-xxx",
    "tokensBefore": 4500,
    "tokensAfter": 500
  }
}
```

## 阈值调整建议

| 场景 | 建议值 | 说明 |
|------|--------|------|
| 高频对话 | `5000` | 更快归档，减少单 session 数据量 |
| 低频对话 | `15000` | 减少归档频率，降低 overhead |
| 调试阶段 | `1000` | 更容易触发，方便验证 |
| 生产环境 | `8000`（默认） | 平衡归档频率和记忆新鲜度 |
