# 消息捕获

## 概述

消息捕获负责将对话内容写入 OpenViking session 存储。由于 Higo V2 协议的拆分，捕获分为两个阶段：

- **Transform 阶段**：捕获当前用户输入（`user` 角色）
- **Result 阶段**：捕获 assistant 回复和 tool 结果

---

## Transform 阶段捕获

### 消息分类

Higo transform 请求的消息列表格式固定为 `[system, user(context), user(current)]`。

`_capture_messages()` 按角色分类：
- `system` → 合并到 current user 的 parts 中
- `user(current)` → 唯一需要捕获的消息
- `user(context env)` → 跳过（环境信息，非用户发言）

### System 合并策略

将 system content 作为 `[system] ...` 前缀合并到 current user 的 text part 中：

```python
for part in parts:
    if part.get("type") == "text":
        user_text = part.get("text", "")
        part["text"] = f"[system] {system_text}\n\n{user_text}"
        break
```

### 文本清洗

调用 `sanitize_user_text_for_capture()` 过滤：
- HEARTBEAT 消息（完全过滤）
- Compacted system messages（提取实际内容）
- `<relevant-memories>` 块
- Conversation metadata 块
- Sender metadata 块
- `<think>` 块
- Fenced JSON metadata 块
- 前导时间戳前缀
- Null bytes

### 捕获决策

`get_capture_decision()` 判断文本是否应该捕获：

| 过滤条件 | 说明 |
|---------|------|
| 空文本 | 清洗后为空则跳过 |
| 长度超限 | `< min_length` 或 `> capture_max_length` |
| 命令文本 | 纯命令格式（如 `/help`） |
| 纯标点 | 仅包含标点、符号和空白 |
| Subagent context | 以 `[Subagent Context]` 开头 |
| 纯问句 | 以问号/疑问词结尾且无 memory intent |

**Mode 分支**：
- `semantic`（默认）：通过上述过滤即捕获
- `keyword`：额外匹配 7 组 trigger regex 才捕获

## Result 阶段捕获

### RoundId 幂等性

`capture_round_result()` 以 `roundId` 为键做去重：
- 内存中维护 `_processed_round_ids` set
- 最多保留最近 1000 个 roundId
- 重复收到相同 roundId 直接返回 0

### Assistant 捕获

`section.type == "content"`：
1. `sanitize_user_text_for_capture()` 清洗
2. 构建 `parts=[{"type": "text", "text": ...}]`
3. `add_session_message(role="assistant", role_id="assistant")`

### Tool 捕获

`section.type == "tool"`：
1. 构建 tool part：`{"type": "tool", "tool_id", "tool_name", "tool_input", "tool_output"}`
2. `add_session_message(role="user", role_id="user")`

> OV 中 tool 结果作为 user 角色的 tool part 存储，与 openclaw-plugin 一致。
