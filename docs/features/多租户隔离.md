# 多租户隔离

## 概述

每个 Higo 用户在 OpenViking 中拥有独立的 account + USER key，实现 session、memories、resources 的物理隔离。

---

## 核心设计

### 映射关系

```
Higo userId (UUID)  →  higo_{userId}  →  OpenViking account_id
                                    →  OpenViking user_id (default)
                                    →  USER key
```

### 权限模型

| Key 类型 | 用途 | 权限范围 |
|---------|------|---------|
| ROOT key | Admin 操作（创建 account、注册 user） | 全局 |
| USER key | 业务 API（session、search、commit） | 单个 account |

---

## AccountRegistry

### 职责

管理 `higo_user_id → {account_id, user_id, api_key}` 映射：
- 内存缓存（`self._cache: dict[str, OpenVikingClient]`）
- 本地持久化（`.account_registry.json`，atomic write）
- 懒创建（`asyncio.Lock` + 双重检查）

### 懒创建流程

```
get_client("higo_u001")
    ├──► 查缓存：命中 → 直接返回
    ├──► 查 registry：命中 → 构建 Client
    └──► 懒创建：
         ├──► GET /admin/accounts 检查存在
         ├──► POST /admin/accounts 创建（如不存在）
         ├──► POST /admin/accounts/{id}/users 注册 user
         │    └──► 409 Conflict → POST /users/{uid}/key regenerate
         └──► 原子写入 .account_registry.json
```

### 持久化格式

```json
{
  "higo_u001": {
    "account_id": "higo_u001",
    "user_id": "default",
    "api_key": "xxx.xxx.xxx",
    "created_at": "2026-06-02T..."
  }
}
```

---

## Fallback 行为

不带 `userId` 的请求（向后兼容）：
- 使用 `admin_client`（ROOT key）
- 数据落到 `default` account
- 行为与旧版一致
