# 记忆注入

## 概述

记忆注入是 transform 阶段的最后一步，将组装好的记忆文本作为独立 `user` 消息插入到消息列表中，返回给 Higo。

---

## 消息重建规则

### 输入

Higo 发送的原始消息列表：
```
[0] system
[1] user (context environment)
[2] user (current user message)
```

### 输出

`_build_messages()` 在**第一个 user 消息之前**插入 memory 消息：
```
[0] system                    ← 保留，位置不变
[1] user (memory)             ← 注入
[2] user (context environment) ← 保留
[3] user (current user)       ← 保留，必须是最后一条 user
```

### 核心不变量

Higo 会严格校验：
1. `result.request` 只能包含 `messages` 一个字段
2. 必须完整保留 system、contextEnv、currentUser 三条消息
3. 最后一条 `role="user"` 必须是 currentUser

---

## Memory Text 结构

### 完整格式（含会话历史）

```
<session-history>
  [归档摘要]
  旧摘要内容

  [最近归档摘要]
  最新摘要内容

  - user: 之前的用户输入
  - assistant: 之前的模型回复
</session-history>

<relevant-memories>
  - [profile] 用户档案内容 (95%)
  - [preferences] 偏好内容 (88%)
  - [entities] 实体内容 (82%)
</relevant-memories>
```

### 简化格式（无会话历史）

当 `history_budget <= 0` 或无可用的 session context 时，只输出：
```
<relevant-memories>
  - [profile] ...
</relevant-memories>
```

### 空记忆

当搜索无结果且无可用的 session history 时，`memory_text` 为空字符串，跳过注入（Higo 收到原始消息列表不变）。

---

## 组装逻辑

`_assemble_memory_text()` 的职责：
1. 如果有 `session_history`，前置 `<session-history>` 区块
2. 如果有 `memories`，追加 `<relevant-memories>` 区块
3. 用 `\n\n` 连接两个区块
4. 两者都为空则返回空字符串
