# 会话历史

## 概述

当 Higo 配置记忆引擎后，原始消息列表中不含历史对话内容。higo2ov 通过 OpenViking 的 `get_session_context()` 获取会话上下文，将归档摘要和活跃消息组装为 `<session-history>` 区块注入到对话中。

---

## 数据源

`get_session_context()` 返回：

| 字段 | 类型 | 说明 |
|------|------|------|
| `latest_archive_overview` | string | 最近一次 commit 的摘要 |
| `pre_archive_abstracts` | list[string] | 更早的 commit 摘要列表（旧→新排序） |
| `messages` | list[dict] | 尚未 commit 的活跃消息 |
| `estimatedTokens` | int | 活跃消息的估算 token 数 |

---

## Token 预算分配

```
total_budget = modelContextWindowTokens * 0.85
fixed_costs = system_message_tokens + contextEnv_tokens + currentUser_tokens + 2048(reserved)
history_budget = max(0, (total_budget - fixed_costs) * 0.85)
```

- `2048` 为固定预留开销
- token 估算使用 `utils/token_utils._count_tokens()`（优先 tiktoken，fallback 字符估算）
- `<relevant-memories>` 使用独立的 `recall_token_budget`，不与历史预算竞争

---

## 截断策略

组装后的条目按时间顺序排列（旧→新）：

```
[pre_archive_abstracts[0]]      ← 最旧，先丢
[pre_archive_abstracts[1]]
...
[latest_archive_overview]        ← 保留
- user: ...                      ← 旧消息，先丢
- assistant: ...
- user: ...                      ← 最新消息，保留
```

截断从 newest→oldest 遍历选取，reverse 输出为 chronological：
1. 最旧的 `pre_archive_abstracts` 先被丢弃
2. 然后是旧的活跃 `messages`
3. `latest_archive_overview` 和最新消息始终保留

### 格式化规则

- 归档摘要：`[归档摘要]
{text}`，截断到 800 字符
- 活跃消息：`- {role}: {text}`，截断到 500 字符
- 排除当前轮次最后一条消息（避免与 Higo 的 currentUser 重复）

---

## 输出结构

```
<session-history>
  [归档摘要]
  旧摘要内容

  [最近归档摘要]
  最新摘要内容

  - user: 之前的用户输入
  - assistant: 之前的模型回复
</session-history>
```

若 `history_budget <= 0`，整个区块为空字符串，不输出。

---

## 与 OV Commit 的协作

| 阶段 | higo2ov 注入内容 | OV 状态 |
|------|-----------------|---------|
| 新会话首轮 | 无 `<session-history>` | 无归档 |
| commit 前 | 完整活跃 messages | pending_tokens 累积 |
| commit 后 | `latest_archive_overview` + 新活跃 messages | 已有归档摘要 |
| 多次 commit | `pre_archive_abstracts` + `latest_archive_overview` + 活跃 messages | 多层归档 |
