# Higo V2 协议说明

## 协议概览

Higo V2 协议（`protocolVersion: "2026-05-25"`）定义了 Higo 与记忆引擎插件之间的通信规范。higo2ov 实现了四种模式：

| 模式 | 触发时机 | 功能 |
|------|---------|------|
| `probe` | Higo 心跳/测试 | 连通性检查 |
| `transform` | 每轮用户输入 | 召回记忆 + 捕获消息 + 注入 memory |
| `result` | Round 结束 | 捕获 assistant/tool 结果 |
| `memory_query` | 独立调用 | 记忆查询（当前为占位实现） |

---

## 请求模型

### ProbeRequest

```json
{
  "mode": "probe",
  "protocolVersion": "2026-05-25",
  "source": "higo",
  "session": {"sessionId": "xxx", "contextPath": "/", "userId": "u001"},
  "timestamp": "2026-05-26T10:00:00Z"
}
```

### TransformRequest

```json
{
  "mode": "transform",
  "protocolVersion": "2026-05-25",
  "source": "higo",
  "session": {"sessionId": "xxx", "contextPath": "/", "userId": "u001"},
  "round": {"roundId": "r001", "seq": 1, "startedAt": "2026-05-26T10:00:00Z"},
  "request": {
    "messages": [
      {"role": "system", "content": "你是一个助手"},
      {"role": "user", "content": "Context environment: ..."},
      {"role": "user", "content": "当前用户输入"}
    ]
  },
  "meta": {"modelContextWindowTokens": 128000}
}
```

**关键字段**：
- `session.sessionId` — 会话标识
- `session.userId` — 用户标识（可选，用于多租户隔离）
- `round.roundId` / `round.seq` — 轮次信息
- `request.messages` — 消息列表 `[system, user(context), user(current)]`
- `meta.modelContextWindowTokens` — 模型上下文窗口大小

### ResultRequest

```json
{
  "mode": "result",
  "protocolVersion": "2026-05-25",
  "source": "higo",
  "session": {"sessionId": "xxx", "userId": "u001"},
  "round": {"roundId": "r001", "seq": 1, "status": "completed"},
  "transform": {"applied": true},
  "message": {
    "seq": 1,
    "usermsg": "当前用户输入",
    "systemPrompt": "你是一个助手",
    "contextEnvironment": "",
    "sections": [
      {"subSeq": 0, "type": "content", "content": "Assistant 回复"},
      {"subSeq": 1, "type": "tool", "toolname": "search", "toolCallId": "call-1", "toolargs": "{}", "toolrsp": "{}"}
    ]
  },
  "errors": []
}
```

**Section 类型**：
- `content` — assistant 文本回复
- `tool` — tool 调用结果
- `reasoning` — 模型推理过程（不 capture）

## 响应模型

### TransformResponse

```json
{
  "ok": true,
  "summary": "transform ok",
  "result": {
    "request": {
      "messages": [
        {"role": "system", "content": "你是一个助手"},
        {"role": "user", "content": "<session-history>...<relevant-memories>..."},
        {"role": "user", "content": "Context environment: ..."},
        {"role": "user", "content": "当前用户输入"}
      ]
    },
    "pluginContext": {"memoryRevision": "higo-ov-r1"}
  }
}
```

### ResultResponse

```json
{
  "ok": true,
  "summary": "result accepted",
  "ack": {
    "roundId": "r001",
    "stored": true,
    "memoryRevision": "higo-ov-r1"
  }
}
```

## 消息重建顺序

`_build_messages` 的核心不变量：

```
[0] system                    ← 保留，位置不变
[1] user (memory)             ← 注入的记忆消息
[2] user (context environment) ← 保留，位置不变
[3] user (current user)        ← 保留，必须是最后一条 user
```

Higo 会严格校验：
1. `result.request` 只能包含 `messages` 一个字段
2. 必须完整保留 system、contextEnv、currentUser 三条消息
3. 最后一条 `role="user"` 必须是 currentUser
