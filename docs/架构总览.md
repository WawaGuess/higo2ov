# 架构总览

## 系统架构

```
┌─────────────┐      HTTP POST       ┌──────────────────────┐      HTTP      ┌─────────────────┐
│    Higo     │ ───────────────────► │    higo2ov           │ ─────────────► │   OpenViking    │
│  (Server)   │  mode=probe          │  (FastAPI Plugin)    │                │    (Server)     │
│             │  mode=transform      │  Port: 8000          │                │  Port: 1933     │
│             │  mode=result         │                      │                │                 │
└─────────────┘                      └──────────────────────┘                └─────────────────┘
       ▲                                                                            ▲
       │                                                                            │
       └─────────────────────────── 对话消息流 ─────────────────────────────────────┘
```

**请求流向**：
1. Higo 将用户消息发送给 higo2ov（`POST /`，`mode=transform`）
2. higo2ov 调用 OpenViking API 进行记忆召回和消息捕获
3. higo2ov 将注入记忆后的消息返回给 Higo
4. Higo 调用 LLM 生成回复
5. Round 结束时 Higo 将结果回调给 higo2ov（`POST /`，`mode=result`）
6. higo2ov 将 assistant 回复和 tool 结果写入 OpenViking

## 一个 Round 的完整链路

### Transform 阶段（用户发消息）

```
Higo POST / (mode=transform)
    │
    ├──► session_to_ov_id()          UUID → OV ID 映射
    ├──► bypass check                跳过白名单 session
    ├──► resolve agent_id            从 sessionId 提取或 config fallback
    ├──► resolve client              多租户：cache → registry → lazy create
    │
    ├──► Step 1: Capture user        当前 user 消息存入 OV session
    │       - 分类：system / user(current) / user(context env)
    │       - system 合并到 current user parts
    │       - sanitize：过滤 HEARTBEAT、think、metadata
    │
    ├──► Step 2: Get Context         GET /sessions/{id}/context
    │       - latest_archive_overview
    │       - pre_archive_abstracts
    │       - active_messages
    │
    ├──► Step 3: Assemble History    归档摘要 + 活跃消息 → <session-history>
    │       - token 预算截断
    │
    ├──► Step 4: Recall Memories     POST /search/find × 2 (user + agent)
    │       - 去重 → query-aware 排序 → leaf 优先 → 预算截断
    │       - 组装 <relevant-memories>
    │
    ├──► Step 5: Assemble            session_history + relevant_memories
    │
    ├──► Step 6: Build Messages      在第一个 user 前插入 memory
    │       [system, user(memory), user(contextEnv), user(current)]
    │
    ├──► Step 7: Monitor             TurnCollector.start_turn()
    │
    └──► Step 8: Async Commit        _maybe_commit() 异步触发
    │
    └──► 返回 TransformResponse
```

### Result 阶段（LLM 回复完成）

```
Higo POST / (mode=result)
    │
    ├──► roundId 去重检查
    ├──► resolve client
    │
    ├──► Capture assistant           sections type=content → sanitize → 存 OV
    ├──► Capture tool                sections type=tool → parts → 存 OV
    │
    ├──► Async Commit                _maybe_commit()
    ├──► Monitor                     TurnCollector.end_turn()
    │
    └──► 返回 ResultResponse
```

## 关键不变量

1. **消息顺序**：`_build_messages` 输出必须是 `[system, user(memory), user(contextEnv), user(current)]`
2. **currentUser 位置**：最后一条 `role="user"` 必须是当前用户输入
3. **幂等性**：`capture_round_result` 以 `roundId` 为键去重
4. **异步不阻塞**：`_maybe_commit` 使用 `asyncio.create_task`，不阻塞 Higo 响应
